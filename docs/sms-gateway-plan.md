# iSMS Gateway Server — план

Сервер, к которому подключаются телефоны с приложением [iSMS GW](https://github.com/iSmartyPRO/isms-gw-android)
(режим «Persistent link / SMS server»). Пользователи сами добавляют свои телефоны, управляют SIM-картами,
отправляют и получают SMS через веб-интерфейс и REST API, раздают доступ коллегам и интеграциям.

## 1. Что умеет телефон (протокол, `net/RemoteClient.kt`)

Телефон сам открывает WebSocket к серверу (работает за NAT и на мобильном интернете):

```
GET wss://<server>/ws/device
Authorization: Bearer <device token>
X-Device-Id: <uuid телефона>   X-Device-Name: <имя>   User-Agent: iSMS-GW/<версия>
```

| Направление | Кадр | Поля |
|---|---|---|
| телефон → сервер | `hello` | `deviceId`, `deviceName`, `version`, `sims[]` (SimInfo) |
| | `event` | `event` = `sms.received` / `sms.sent` / `sms.delivered` / `sms.failed`, `data` = Message |
| | `ack` | ответ на `send`: `id` (наш ref), `to`, `messageId` (id на телефоне), `status` |
| | `error` | ответ на `send`: `id`, `to`, `error` (лимит, фильтр направлений, нет SIM…) |
| | `status` | `sims[]`, `stats` (на `get_status`) |
| | `pong` | на `ping` |
| сервер → телефон | `send` | `id` (ref), `to` (строка или массив), `text`, `sim` (слот; 0 = стратегия телефона) |
| | `ack_event` | `messageId` — входящее принято; иначе телефон пришлёт его снова после переподключения |
| | `get_status` | запросить SIM и статистику |
| | `ping` | проверка связи |

Message: `id, direction, phone, text, sim (слот), simId, status, error, parts, source, ref, createdAt, sentAt, deliveredAt…`.
SimInfo: `simId, slot, active, embedded, carrier, displayName, number, country, label, color, sendEnabled, receiveEnabled, dailyLimit, isDefault, iccTail, lastSeen`.

Ограничения протокола (учтены в сервере):
- статусы исходящих (`sms.sent/delivered/failed`) телефон шлёт, только пока подключён, и не повторяет —
  если связь рвалась, сообщение может «зависнуть» в `accepted`; сервер помечает такие как «статус неизвестен» по таймауту;
- выбрать SIM можно только по **слоту**; USSD и звонки по этому каналу недоступны (только локальный API телефона).

## 2. Архитектура

```
Android (iSMS GW) ──wss /ws/device──► reverse proxy (TLS) ──► sms-server
                                                        │  /ws/device  — WebSocket-хаб (ws), в памяти: deviceId → сокет
Браузер ── https ──► SPA /app/sms                       │  /api/app/sms — REST (сессия) = /api/v1/app/sms (API-токен)
Интеграции ── Bearer pat_… ──► /api/v1/app/sms          │  очередь отправки, диспетчер, вебхуки, уведомления
                                                        ▼
                                                   PostgreSQL sms_*
```

Модуль `sms` на платформе iApp-Skeleton: пользователи, роли, API-токены с областями и лимитами по устройствам,
вебхуки, уведомления, справка, база знаний — всё платформенное.

## 3. Данные

| Таблица | Что |
|---|---|
| `sms_devices` | телефон: владелец, имя, цвет, токен (SHA-256 + префикс), uid/модель/версия с телефона, онлайн, last_seen, IP, лимиты (в минуту, в день), включён |
| `sms_device_acl` | доступ к телефону: пользователь / группа / роль / все; `view` (читать), `edit` (отправлять), `manage` (настраивать, делиться, токен) |
| `sms_sims` | SIM/eSIM телефона: слот, оператор, номер, страна; на сервере — своё имя, цвет, отправка вкл/выкл, дневной лимит |
| `sms_messages` | входящие и исходящие: uuid, телефон, SIM, номер, текст, части, статус, ошибка, ref клиента, batch, отложенная отправка, время этапов |
| `sms_device_events` | журнал телефона: подключился / отключился / токен сменён / ошибка (хранится 30 дней) |
| `sms_templates` | шаблоны сообщений (личные и общие) |

Статусы исходящих: `scheduled → queued → dispatched → accepted → sent → delivered`, либо `failed` / `cancelled` / `expired`.

## 4. Отправка и маршрутизация

- `POST /messages` — один или до 1000 получателей (batch), номера в E.164 (libphonenumber, страна по умолчанию — из настроек).
- Куда: конкретная SIM → конкретный телефон → «авто» (телефоны пользователя с правом `edit`, онлайн, SIM с включённой
  отправкой и не исчерпанным дневным лимитом; выбирается наименее загруженная за сегодня).
- Телефон офлайн — сообщение ждёт в очереди и уходит при подключении; не ушло за TTL (по умолчанию 24 ч) → `expired`.
- Диспетчер: темп на телефон (по умолчанию 20 в минуту), ожидание `ack` 60 с, до 3 попыток.
- Отложенная отправка (`sendAt`), отмена в очереди, повтор неудачных.
- Счётчик сегментов: GSM-7 (160/153) и UCS-2 (70/67), с расширенной таблицей GSM.

## 5. API и доступы

- Все эндпоинты модуля — в `/api/v1/app/sms/**` с токенами платформы (`pat_…`), область `sms` (`read` / `write`).
- Токен можно сузить до конкретных телефонов (лимит ресурсов `sms.devices`), IP-списка, срока, частоты.
- Вебхуки: `sms.received`, `sms.sent`, `sms.delivered`, `sms.failed`, `device.online`, `device.offline`
  (подпись HMAC-SHA256, повторы, «выполнять от имени» — видит только доступные телефоны).
- Портал разработчика `/developers` с примерами cURL / JS / Python / PHP генерируется автоматически.

## 6. Интерфейс (`/app/sms`)

| Раздел | Что |
|---|---|
| Обзор | KPI за сегодня, график 14 дней, телефоны онлайн, последние события |
| Телефоны | карточки с SIM, мастер «Добавить телефон» (URL + токен + QR, ожидание подключения вживую), страница телефона: SIM, лимиты, токен, журнал, доступ |
| Сообщения | диалоги (чат по номеру) и таблица со фильтрами, экспорт CSV |
| Отправить | получатели (вставка списком), шаблоны, выбор SIM/авто, счётчик сегментов, предпросмотр, отложенная отправка |
| API | базовый URL, создание токена, примеры кода, события вебхуков |

Языки: English, Русский, Türkçe (ky/zh — английский по умолчанию). Тёмная тема, телефоны.

## 7. Главная и база знаний

- Главная (`/`) — лендинг iSMS Gateway: возможности, как подключить, пример API, безопасность, сценарии, FAQ — EN / RU / TR.
- База знаний: папки на трёх языках — быстрый старт, настройка Android (батарея, Samsung, Xiaomi), API и вебхуки с примерами,
  кодировки и сегменты SMS, формат номеров E.164, как не попасть под блокировку оператора, безопасность, диагностика.

## 8. Этапы

1. ✅ Изучение протокола и платформы, план.
2. Backend: схема, протокол WebSocket, диспетчер, REST, права, лимиты токенов, вебхуки, уведомления; unit-тесты.

4. Frontend модуля: обзор, телефоны, сообщения, отправка, API; переводы EN/RU/TR; справка.
5. Главная страница EN/RU/TR, настройки портала (название, языки, главная).
6. База знаний — статьи на трёх языках.
7. Тесты: `npm test`, `i18n:check`, сборка; e2e с эмулятором телефона (Node-скрипт, тот же протокол).
8. Пересборка контейнера, проверка через публичный HTTPS-адрес.

Потом (не в базовой версии): git-репозиторий, контакты и группы рассылок, входящие правила (автоответ, пересылка),
отчёты и биллинг по пользователям, мульти-инстанс (Redis для хаба).
